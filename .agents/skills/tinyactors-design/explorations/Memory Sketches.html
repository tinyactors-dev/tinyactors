Exploration · memory

Memory sketches

Five new components for byte order, wire format, rings and cross-core access, alternate treatments of RingBuffer and MemoryLayout, and one motion language for read and write heads. All examples are illustrative.

Section 1

New components

Each is a separate component idea, not a variant of an existing one.

1a

ByteOrder

The same 32-bit value at ascending addresses. A load head reads bytes in address order and assembles the register, so you can see where each byte lands.

uint32_t x = 0x0A0B0C0D; // &x = 0x1000
1b

WireLayout

A protobuf message on the wire: tag bytes, varints and length-delimited payloads. A decode head walks the bytes and the panel explains each one.

message Event { uint32 id = 1; string type = 2; } // { id: 300, type: "PAY" } · 8 bytes
1c

SpscRing

One writer, one reader, live. Sequence numbers only increase and the slot is seq & 7. The writer comes in bursts, so the ring fills, blocks and drains.

1d

BroadcastRing

One writer, three readers with their own cursors. Pips show which readers have consumed a slot. A slot is freed only after the slowest reader passes it, so that reader gates the writer.

1e

CacheLineAccess

Which core owns which cache line, and what a write costs. With tail and head on one line, each write moves the line to the other core. On separate 64 B lines, each line stays with its core.

Section 2

Variations of existing components

2a–2c render the same live buffer as 1c, so you can compare views of one state. 2d–2f show the same struct actor_hdr as MemoryLayout.

2a

RingBuffer · dial

Drawn as a ring. Heads rotate by sequence number, so they always move clockwise and wrapping needs no special case.

2b

RingBuffer · sequence tape

Unrolled into sequence space. The capacity-8 window slides along the tape, with the physical slot under each number. Wrapping shows up as modulo, not as a jump.

2c

RingBuffer · inline meter

A 30px row for the inspector's actor tree and mailbox columns. The dashed cell is the next write. The first row follows 1c.

2d

MemoryLayout · listing

One row per field, like pahole, with a byte bar on a shared ruler. Suits long structs that get too wide as a grid.

2e

MemoryLayout · reorder

Before and after at the same scale, so the saving reads as length. Fields sorted by alignment; the holes disappear.

2f

MemoryLayout · hex map

One instance as raw bytes, 16 per row, tinted by field. Little-endian values read backwards, which ties it to 1a.

Section 3

Motion language: read and write heads

Seven primitives, each with its own duration and easing. These animations run on their own, without user input, so they use Material's longer ambient range. Heads use in-out easing because they stay visible the whole time. Things arriving decelerate, things leaving accelerate and finish sooner. Use Speed ¼× to inspect them.

PrimitiveDurationEasingMeans
step420msin-out · .45 0 .2 1A head advances one slot. It starts moving at 60% of the fill, so the two actions overlap instead of queueing.
fill480msdecelerate · .05 .7 .1 1Bytes are stored. The fill sweeps in address order and the value drops in from the head. Dashed pine border: reserved, not yet visible.
publish240ms in · 900ms outdecelerate in · accelerate outRelease store. The dashed border crossfades to a solid pine ring, which then trails off as follow-through.
drain360msaccelerate · .3 0 .8 .15The value drops 8px toward the read head and fades. Shorter than fill because exits need less attention.
block240ms, then heldin-outThe head and a dashed inset fade to ochre and hold until the slot frees.
wrap240ms exit · 240ms enter · 700ms pulsein-outThe head runs past the last slot and fades out, then fades in at slot 0 while a pulse runs back along the wrap line.
transfer700msin-outA cache line moves between cores. Madder dot on a dashed trace. Only used for coherence cost.
  1. Heads only move forward. Wrapping is an exit and re-entry, never a head sliding back across the buffer.
  2. Overlap, don't queue. Each action starts before the previous one has fully settled, so a write reads as one gesture.
  3. Nothing switches instantly. Every state change, including reset and blocking, fades or moves. Highlights trail off rather than disappearing.
  4. Color carries role. Write heads are pine, read heads graphite. Ochre only for blocking and back-pressure, madder only for coherence traffic.
  5. One clock. All durations scale by a single factor, so slow motion stays consistent across components.
  6. Reduced motion keeps the information. Durations drop to zero but every state change still renders.
