# Ship a generated C parser

This guide is for a host author who has a grammar that works with the VM and
wants it compiled into the program. A generated parser is C code with one
function per rule and token, and it builds the same tree and diagnostics as the
VM. At the end your program links a generated parser and drives it through
the ordinary parser API.

## Prerequisites

- A source tree built with `mise run build`, the shell in its `tinyparse/`
  directory, and `tinyparse` on `PATH` (`export PATH="$PWD/build/bin:$PATH"`);
  see [Install tinyparse](install.md). A release tarball or an amalgamation
  alone does not build a generated parser: the generated file includes the
  library's private header `src/internal.h` and calls internal `tp_*`
  functions, which `libtinyparse.a` and the amalgamation's `tinyparse.c`
  define and the shared library does not export.
- The generated file and the library come from the same source tree. Compile
  the file with `-I include -I src`, and link it with `build/lib/libtinyparse.a`
  or with `dist/amalgamation/tinyparse.c` (`mise run amalgamate`).
- A C11 compiler for the generated file; the host program can be C99.
- A scratch directory:

  ```sh
  WORK="$(mktemp -d)"
  ```

## Generate the parser

`tinyparse c` writes a generated parser in one of two shapes:

| Flag | The file holds |
|------|----------------|
| `--parser` | The parser and a `main` that reads standard input, prints the tree in the format of `tinyparse run --dump-tree`, and exits with status 1 on a failed parse. Its grant is a 1 GiB static array. |
| `--parser-lib` | The parser and its entry points, without `main`, to link into a host program. |

Generate the library shape for `examples/sexpr/sexpr.scm`:

```sh
tinyparse c examples/sexpr/sexpr.scm --parser-lib --out "$WORK/sexpr_parser.c"
```

## Name the entry points

Every file-scope name in the file starts with a prefix `P` and an underscore.
The prefix is the grammar's name, the name after `(grammar`, unless `--name P`
sets it. `examples/sexpr/sexpr.scm` starts with `(grammar sexpr`, so the file
above defines these three functions, and its internal functions are `static`
and named like `sexpr_parse_List_8` and `sexpr_scan_Atom_6`:

```c
tinyparse_result sexpr_load(tinyparse_engine *engine, tinyparse_grammar **out_grammar);
tinyparse_result sexpr_run(tinyparse_parser *parser);
tinyparse_result sexpr_run_chunk(tinyparse_parser *parser);
```

- `P_run_chunk` exists only when the start rule is a top-level repetition
  ([P_run_chunk](../reference/c-api.md#p_run_chunk) gives the forms); the
  start rule of `sexpr`, `(seq (repeat Form) EOF)`, is one.
- `--name` is copied into the file as written. Give it a valid C identifier;
  `tinyparse c` does not check it.
- The file declares no header. Declare the entry points you call in your
  program, as below.

The [Generated parser interface](../reference/c-api.md#generated-parser-interface)
reference specifies each entry point.

## Drive the parser

A generated parser uses the ordinary engine, grammar and parser objects. The
program calls `P_load` where it would compile or load a grammar, and `P_run`
where it would call `tinyparse_finish`; everything else, from pushing input to
walking the tree, is the [C API](../reference/c-api.md) as with the VM.

1. Save this program as `$WORK/host.c`. It parses a fixed string and prints
   each node's kind and byte range:

   ```c
   #include <stdio.h>
   #include <stdlib.h>
   #include <string.h>

   #include "tinyparse.h"

   /* Defined in sexpr_parser.c, generated by `tinyparse c --parser-lib`. */
   tinyparse_result sexpr_load(tinyparse_engine *engine, tinyparse_grammar **out_grammar);
   tinyparse_result sexpr_run(tinyparse_parser *parser);

   #define GRANT_SIZE (1024u * 1024u)

   static void print_tree(const tinyparse_tree *tree, tinyparse_tree_cursor *cursor)
   {
       uint32_t depth = tinyparse_tree_cursor_depth(cursor);
       tinyparse_string kind = tinyparse_tree_symbol_name(tree, tinyparse_tree_cursor_kind(cursor));
       uint32_t i;

       for (i = 0; i < depth; i++)
           fputs("  ", stdout);
       printf("%.*s [%u-%u]\n", (int)kind.length, (const char *)kind.pointer,
              (unsigned)tinyparse_tree_cursor_start_byte(cursor),
              (unsigned)tinyparse_tree_cursor_end_byte(cursor));
       if (tinyparse_tree_cursor_goto_first_child(cursor)) {
           do
               print_tree(tree, cursor);
           while (tinyparse_tree_cursor_goto_next_sibling(cursor));
           tinyparse_tree_cursor_goto_parent(cursor);
       }
   }

   int main(void)
   {
       static const char text[] = "(define x 1)";
       tinyparse_configuration configuration;
       tinyparse_engine *engine;
       tinyparse_grammar *grammar = NULL;
       tinyparse_parser *parser = NULL;
       tinyparse_tree_cursor *cursor = NULL;
       tinyparse_string no_start = { NULL, 0 };
       tinyparse_string input;
       tinyparse_result result;
       void *grant = malloc(GRANT_SIZE);
       int status = 1;

       if (grant == NULL)
           return 1;
       memset(&configuration, 0, sizeof configuration);
       configuration.memory.base = grant;
       configuration.memory.size = GRANT_SIZE;
       engine = tinyparse_open(configuration);
       if (engine == NULL) {
           fputs("tinyparse_open failed\n", stderr);
           free(grant);
           return 1;
       }

       if (sexpr_load(engine, &grammar) != TINYPARSE_OK) {
           tinyparse_string fault = tinyparse_fault(engine);
           fprintf(stderr, "sexpr_load: %.*s\n", (int)fault.length, (const char *)fault.pointer);
           goto done;
       }
       result = tinyparse_parser_new(engine, grammar, no_start, &parser);
       if (result != TINYPARSE_OK) {
           fprintf(stderr, "tinyparse_parser_new failed: %d\n", (int)result);
           goto done;
       }
       input.pointer = (const uint8_t *)text;
       input.length = (uint32_t)strlen(text);
       result = tinyparse_push(parser, input);
       if (result != TINYPARSE_OK) {
           fprintf(stderr, "tinyparse_push failed: %d\n", (int)result);
           goto done;
       }

       /* The generated parser takes the place of tinyparse_finish. */
       result = sexpr_run(parser);
       if (result != TINYPARSE_OK) {
           uint32_t i, count = tinyparse_parser_diagnostic_count(parser);
           for (i = 0; i < count; i++) {
               const tinyparse_diagnostic *d = tinyparse_parser_diagnostic(parser, i);
               fprintf(stderr, "%.*s [%.*s]\n", (int)d->message.length, (const char *)d->message.pointer,
                       (int)d->code.length, (const char *)d->code.pointer);
           }
           goto done;
       }
       result = tinyparse_tree_cursor_new(tinyparse_parser_tree(parser), &cursor);
       if (result != TINYPARSE_OK) {
           fprintf(stderr, "tinyparse_tree_cursor_new failed: %d\n", (int)result);
           goto done;
       }
       print_tree(tinyparse_parser_tree(parser), cursor);
       tinyparse_tree_cursor_free(cursor);
       status = 0;

   done:
       if (parser != NULL)
           tinyparse_parser_free(parser);
       if (grammar != NULL)
           tinyparse_grammar_free(grammar);
       tinyparse_close(engine);
       free(grant);
       return status;
   }
   ```

2. Compile the generated file and the program, then link both with the
   library. The generated file is compiled without `-Wall -Wextra`, under which
   it reports unused functions and labels:

   ```sh
   cc -std=c11 -O2 -I include -I src -c "$WORK/sexpr_parser.c" -o "$WORK/sexpr_parser.o"
   cc -std=c99 -Wall -Wextra -pedantic -I include -c "$WORK/host.c" -o "$WORK/host.o"
   cc "$WORK/host.o" "$WORK/sexpr_parser.o" build/lib/libtinyparse.a -o "$WORK/host"
   ```

3. Run it:

   ```sh
   "$WORK/host"
   ```

   ```text
   Source [0-12]
     Form [0-12]
       List [0-12]
         ( [0-1]
         Form [1-7]
           Atom [1-7]
         Space [7-8]
         Form [8-9]
           Atom [8-9]
         Space [9-10]
         Form [10-11]
           Atom [10-11]
         ) [11-12]
   ```

Each rule call is a C function call. Past 1,000 nested rule calls, `P_run`
fails with `TINYPARSE_SYNTAX_ERROR` and a `parse.syntax` diagnostic instead of
overflowing the C stack.

## Parse a buffer that is still growing

With `P_run_chunk`, the program parses the top-level items that have arrived
while the rest of the input is still coming. It sets the parser's
`input_complete` field, which `src/internal.h` declares, so the program
includes that header and compiles with `-I src`. This fragment follows the loop
of `examples/bufferfriendly/bufferfriendly.c`, which uses the prefix `sx`;
`next_chunk` stands for the program's own source of bytes:

```c
#include "internal.h" /* for parser->input_complete */

/* ... after sexpr_load and tinyparse_parser_new ... */
for (;;) {
    tinyparse_string bytes;
    int last = next_chunk(&bytes);      /* 1 when no more bytes will come */

    if ((result = tinyparse_push(parser, bytes)) != TINYPARSE_OK)
        break;                          /* TINYPARSE_OUT_OF_MEMORY */
    parser->input_complete = last;
    result = sexpr_run_chunk(parser);
    if (last)
        break;                          /* result is what sexpr_run returns */
    if (result != TINYPARSE_MORE)
        break;                          /* TINYPARSE_OUT_OF_MEMORY */
}
```

Each call before the last returns `TINYPARSE_MORE`, even when the input
already holds a syntax error; the call with `input_complete` set to 1 returns
`TINYPARSE_OK` or `TINYPARSE_SYNTAX_ERROR` and leaves the same tree `P_run`
builds from the whole input. The worked example is
[bufferfriendly](../../examples/bufferfriendly/README.md).

## Link several parsers into one program

Two generated parsers link into one program when their prefixes differ. Their
default prefixes differ when their grammars' names do; give one `--name` when
two grammars share a name, or to choose the names:

```sh
tinyparse c examples/embed/host.scm --parser-lib --name host_parser --out "$WORK/host_parser.c"
tinyparse c std.json --parser-lib --name json_parser --out "$WORK/json_parser.c"
```

Both files share one copy of the library. Each parser loads its own grammar
with its `P_load`; create a parser from that grammar only, and run it with the
same prefix's `P_run`. The [embed](../../examples/embed/README.md) example parses a
document with one generated parser and the regions it finds with another.

A grammar with an [`inject`](../reference/grammar.md#inject) form parses a
region with another grammar during the same parse. To parse that region with
a generated parser, load the injected grammar through its `P_load` and
register it, with its `P_run`, under the name the `inject` form carries,
before the host parse starts. This fragment registers a parser generated from
std.json with `--name json_lang`:

```c
tinyparse_language_entry entry;
tinyparse_grammar *json = NULL;
tinyparse_string language = { (const uint8_t *)"std.json", 8 };

if (json_lang_load(engine, &json) != TINYPARSE_OK)
    return 1;
entry.grammar = json;
entry.parse = json_lang_run;
if (tinyparse_register_language(engine, language, &entry) != TINYPARSE_OK)
    return 1;
```

Register on the engine that runs the host parser. A region whose language has
no registered parser is parsed by the VM, into the same tree.
The [nesting](../../examples/nesting/README.md) example does this for std.fence with
generated std.json and std.javascript parsers; [Registered
languages](../reference/c-api.md#registered-languages) has the rules.

## Build a shared library that exports only the parser

`examples/embed/embed-lib.sh` builds a shared library from the amalgamation
and one or more generated parsers, and exports each parser's `P_load` and
`P_run` and the public `tinyparse_*` functions, and nothing else. It needs
`dist/amalgamation/`, and runs on Linux, where it links with a GNU linker
version script; its macOS branch, which uses `-exported_symbols_list`, is not
run by the build.

1. Build the amalgamation, then the library. Each argument after the output
   is `PREFIX:GRAMMAR`; the script looks for GRAMMAR in `examples/embed/`
   first, then as given, so a path or a standard grammar's name works:

   ```sh
   mise run amalgamate
   bash examples/embed/embed-lib.sh "$WORK/libsexpr.so" sexpr:examples/sexpr/sexpr.scm
   ```

2. Check the exports other than the public API:

   ```sh
   nm -D --defined-only "$WORK/libsexpr.so" | grep -v ' tinyparse_'
   ```

   ```text
   0000000000024f70 T sexpr_load
   0000000000024fd0 T sexpr_run
   ```

`P_run_chunk` is not exported. The program from "Drive the parser" links
against this library with `-L"$WORK" -Wl,-rpath,"$WORK" -lsexpr` in place of
the generated object and `libtinyparse.a`.

## Check the parser against the VM

A generated parser builds the tree and diagnostics the VM builds for the same
grammar and input. `mise run gate:cc-diff` checks that over the test corpus;
[Developing tinyparse](../../DEVELOPMENT.md) describes the gates. For your own
grammar, compare the `--parser` program's output with `tinyparse run
GRAMMAR --input FILE --dump-tree` on the same input.
