# The cases each milestone of the bindings' plan (ROADMAP.md, step 8,
# "Milestones") holds a binding to. `--milestone <name>` runs the lines of
# that milestone and of every milestone above it: the sets are cumulative.
# Without --milestone, the run task runs every suite and every case
# (ta-conform's `mise run conform` does).
#
#   <milestone> protocol <file>…     vector files of suites/protocol (requests,
#                                    config, values), without .txt
#   <milestone> scenarios <name>…    scenarios of suites/scenarios, by directory
#   <milestone> w3c                  the W3C suite, but each skip list's tests
#   <milestone>                      a milestone that adds no case
#
# Every vector file and every scenario is in some milestone: a new one gets
# a line here in the change that adds it (test/milestones_test.rb checks it).
# The datamodels are the binding's conform task's: it runs the set on its
# native datamodel and on quickjs, and both must pass.

# M1, walking skeletons ("Gates"): every protocol vector (values.txt round
# trips through the echo setup on each datamodel), the basics scenario, and
# the outcome canaries, so an adapter that answers pass for everything fails.
M1 protocol requests config values
M1 scenarios basics parallel-history send-errors outcome-compile outcome-fail outcome-timeout

# M2, W3C in each language: the IRP suite, but the skip lists (skip.txt,
# skip-<language>.txt), with BasicHTTP's sends.
M2 w3c

# M3, every effect: invoke and its done events.
M3 scenarios invoke

# M4, lifecycle: hibernation with a store, migration, snapshots.
M4 scenarios hibernate migrate snapshot

# M5, examples and release: the whole suite, nothing it adds.
M5
