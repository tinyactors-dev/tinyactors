# Review of the first Luna implementation commits

The three commits provide useful initial code, but bootstrap and Raw::Value do not meet their full briefs. The original verification run for this review recorded 168 passes and 555 failures. No reviewed commit changed the verifier files. Bootstrap did change production code to satisfy a verifier path check, which exposed a defect in that check.

Reviewed commits: `fdf6d22` (bootstrap), `d973daa` (Result), and `067d07e` (Value). The worktree was clean when the review began. Verification run: `f4d8cb9a551b462c8c1a4b7b96192f04`.

## Findings

1. **P1 — Bootstrap fabricates loaded-feature entries.** In `fdf6d22`, `lib/tinyactors/raw.rb:14–22` adds paths to `$LOADED_FEATURES`. One path omits the dot before the extension. Other paths depend on the caller's working directory or load path. File existence does not establish that Ruby loaded that file. The workaround came from a verifier bug: macOS can canonicalize `/var` to `/private/var`. Fixed the verifier to compare real paths and removed all fabricated entries from the loader. Bootstrap tests now require exactly one existing native feature.

2. **P1 — Value implements a Ruby container, not the specified native ownership boundary.** In `067d07e`, `lib/tinyactors/raw/value.rb` only stores an instance variable. There is no `raw_value.c`, stable C handle indirection, independent core reference accounting, snapshot bridge, or domain ownership check. Its GC test keeps both the payload and wrapper referenced by Ruby. It cannot establish survival under C ownership. This remains open implementation work. The verifier now rejects the Ruby-only implementation. New integration probes exercise queued/current native values, configured snapshots, compaction, event replacement, and teardown through the public C wrappers.

3. **P1 — Bootstrap's resource foundation is absent.** `fdf6d22` exports constants and the text helper, but does not provide the required `support.h`, `support.c`, or `registrations.h`. Owner tokens, native root support, handle factories, callback cleanup, and private native fixtures are not implemented. This remains open implementation work. The new foundation check makes the absent interfaces visible. File presence alone does not establish correctness. The driver's reviewer must inspect their implementation and tests before accepting this milestone.

4. **P2 — The text helper uses a byte count as a character count.** In `fdf6d22`, `tinyactors_raw.c:17` passes `ta_text_t.size` to `rb_str_substr`. For `"λ\0suffix"`, the C prefix length is two bytes, while the Ruby call requests two characters and includes the NUL. Replaced it with `rb_str_subseq`, which takes byte offsets. Added Unicode-plus-NUL and emoji-plus-NUL regression cases to both independent probes and bootstrap tests.

5. **P2 — Result silently coerces invalid statuses.** In `d973daa`, `result.rb:9` uses `Integer(status)`. Both `"0"` and `0.5` become `TA_OK`. The raw contract requires an Integer and preserves programming type errors. Result now raises `TypeError` for nonintegers. Added independent and class-level regression tests. The remaining Result behavior is consistent with its brief.

6. **P2 — The build omits future class implementation files.** In `fdf6d22`, `extconf.rb:14` compiles only `tinyactors_raw.c` plus core sources. Adding an assigned `raw_value.c` or `raw_arena.c` would not build it. The source list now includes local extension C files as well as core C files. Registration remains explicit.

## Consequence for the loop

A rising pass count is useful progress, but it does not establish that a brief is complete. The previous catalog missed some requirements, especially native ownership. The new driver requires independent Sol review before an implementation commit. Review considers the brief and actual source, not only the implementation agent's report.

The driver assigns one milestone at a time. Runtime probes that require later classes remain mandatory at final integration. A milestone commit must preserve every previously passing check and satisfy its current checks. The complete binding requires all checks plus a separate full-binding review.

The concrete loader, text, status, and source-discovery defects were fixed during this review. Native resource foundation and Value ownership remain intentionally open for the implementation loop.
